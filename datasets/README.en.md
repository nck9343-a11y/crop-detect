# Datasets

The datasets under this directory are **not version-controlled** (about 7.5 GB in
total, and the redistribution licence of the main dataset needed confirming — see
below). This file explains what each one is, where it comes from, and how to rebuild
it. 中文版见 [`README.md`](README.md).

## What you need to obtain

| Directory | Contents | Used for | Source |
|---|---|---|---|
| `grape_public/` | 3288 images, 11995 boxes, 6 classes, YOLO format | main experiments E1–E5 | Roboflow, workspace `wscs`, project `grape-uyimv`, version 1 (exported 2025-11-03). **Licence: see below** |
| `grape_coco/` | the same data, COCO format | pycocotools evaluation | COCO export of the same dataset |
| `fieldplant/` | 5156 images, 27 classes (cassava / maize / tomato) | cross-species negative control | [Roboflow Universe: plant-disease-detection/fieldplant v11](https://universe.roboflow.com/plant-disease-detection/fieldplant/dataset/11), CC BY 4.0 |
| `grape_cf_shrink/` | counterfactual version of the main dataset: boxes of the mosaic class shrunk to the central 25% of their area | counterfactual retraining (main group, paper Section 4.4) | generated by script, see below |
| `grape_cf_drop/` | the main dataset with the mosaic class removed | counterfactual retraining (corroborating group) | generated by script |
| `grape_cf_placebo/` | boxes of the botrytis class shrunk instead | placebo control | generated by script |
| `grape_cf_expand/` | boxes of the black rot class coarsened to whole-leaf level | pre-registered reverse manipulation (Result 5) | generated by script |
| `tomato3/` | tomato subset | early exploration, not used in the paper | extracted from fieldplant by `scripts/prepare.py` |

## Rebuilding the counterfactual datasets

Once `grape_public/` is in place, these commands generate them with no manual step:

```bash
python scripts/Counterfactual_prepare.py              # builds grape_cf_shrink and grape_cf_drop
python scripts/Counterfactual_prepare.py --only e12   # builds grape_cf_placebo
python scripts/Counterfactual_prepare.py --only e13   # builds grape_cf_expand
```

The scripts modify annotation boxes only; images are copied unchanged. The shrink
operation keeps the centre fixed and multiplies width and height by 0.5, so the area
becomes 25% of the original. It is applied only to the target class: the symptom of
mosaic virus is a diffuse mottling over the whole leaf, so a box cropped to the centre
still contains genuine symptomatic tissue. The same does not hold for a localised
circular lesion such as black rot (paper Section 4.4).

## Directory conventions

Each dataset is split `train` / `valid` / `test`, with images and annotations in
separate `images/` and `labels/` directories.

Note that a Roboflow-exported `data.yaml` contains relative paths of the form
`train: ../train/images`; concatenated with `path:` these point *outside* the dataset
directory, and only the framework's fallback search makes them work at all. The yaml
files generated by `Counterfactual_prepare.py` use corrected relative paths.

## Licence of the main dataset

`grape_coco/README.dataset.txt` — the attribution statement Roboflow generates on
download — records:

```
# grape > 2025-11-03 9:39am
https://universe.roboflow.com/wscs/grape-uyimv
Provided by a Roboflow user
License: CC BY 4.0
```

So the dataset is published on Roboflow **Universe** under **CC BY 4.0**: it may be
redistributed, with attribution. Section 2.1 of the paper gives the address above as
the attribution.

One inconsistency in the records is worth flagging: the `roboflow:` block of
`grape_public/data.yaml` states `license: Private` with an `app.roboflow.com/...`
address (an internal workspace link). The two files come from different export routes
— `grape_coco` was downloaded from Universe, `grape_public` was exported from the
workspace — and the latter's licence field reflects the workspace setting at export
time, not the licence the project declares publicly. `README.dataset.txt` is
authoritative.

FieldPlant is likewise CC BY 4.0; the citation is reference [10] of the paper.

**On redistributing with this repository.** CC BY 4.0 permits redistribution, so the
only reason for not uploading the data is size (7.5 GB of images). If you need to
check the granularity statistics of Tables 2 and 16 and Figure 1, it is enough to
distribute the annotation files alone (the YOLO-format `labels/`, a few MB in total)
while keeping the attribution above.
